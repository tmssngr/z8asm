Based on analyzing your Z80 assembler codebase, here are the **key parts to refactor** for easier Rust conversion, ranked by priority:

---

## 🔴 **HIGH PRIORITY - Structural Issues**

### 1. **Lexer State Management** (`Lexer.java`)
The Lexer has **7 mutable instance fields** (`source`, `line`, `column`, `chr`, plus nested state in closures). This is the hardest to port.

**Refactor to:**
```rust
// Rust-friendly: stateless parser with iterator pattern
struct TokenStream {
    source: Box<dyn Iterator<Item = char>>,
    line: usize,
    column: usize,
}
// OR use a state machine with explicit state passing
fn lex(input: &str) -> impl Iterator<Item = Token> { ... }
```

**Specific changes:**
- Replace `OptionalInt` with Rust's `Option<char>` or `Option<u8>`
- Replace mutable `chr` field with iterator-based approach
- Remove nested anonymous classes (Java's `CharSource` interface) - use traits or simple functions

---

### 2. **Parser's Nested Class** (`Parser.java`)
The `ImmediateCommandProvider` abstract inner class is tightly coupled.

**Refactor to:**
```rust
// Rust: use function closures instead of abstract classes
// Java currently:
private abstract class ImmediateCommandProvider {
    abstract Command create(int immediate);
    abstract Command createLazy(String id, Location loc);
}

// Rust equivalent:
type ImmediateProvider = dyn Fn(u16) -> Result<Command, SyntaxError> +
                         Fn(&str, Location) -> Result<Command, SyntaxError>;
```

---

### 3. **Error Handling** (All files)
Java uses exceptions (`SyntaxException`, `InvalidTokenException`, `UncheckedIOException`).

**Refactor to:**
```rust
// Rust: use Result<T, E> instead of exceptions
// Java:
throw new SyntaxException("message", location);

// Rust:
return Err(SyntaxError::new("message", location));
```

**Impact:** This affects ~50+ locations across the codebase. Create a proper error enum:
```rust
#[derive(Debug)]
enum AssembleError {
    Syntax(String, Location),
    InvalidToken(String, Location),
    Io(std::io::Error),
    // ...
}
```

---

### 4. **Command Mutability Pattern** (`Assembler.java`)
The assembler mutates command lists in place:
```java
commands.set(i, Command.lazyContent2(...));
commands.removeIf(Objects::isNull);
```

**Refactor to:**
```rust
// Rust: use Vec::into_iter().filter().map().collect() pattern
// Instead of in-place mutation, use functional transforms
let commands: Vec<Command> = commands
    .into_iter()
    .filter(|c| !matches!(c, Command::Null))
    .map(|c| resolve_command(c, &labels))
    .collect();
```

---

## 🟡 **MEDIUM PRIORITY - Data Structure Issues**

### 5. **Byte Handling**
Java's `byte` is **signed** (-128 to 127), Rust's `u8` is **unsigned** (0 to 255).

**Refactor to:**
```rust
// Java:
byte[] values = {(byte)0xFF, (byte)0x80}; // [-1, -128]

// Rust:
let values: Vec<u8> = vec![0xFF, 0x80]; // [255, 128]
```

**Every place that does:**
- `(int)values[index] & 0xFF` → just use `u8` directly
- Bit manipulation with bytes needs careful review

---

### 6. **Collection Types**
Java uses `List<Command>`, `Map<String, Integer>`, `ArrayList`, etc.

**Refactor to:**
```rust
// Java: List<Command> commands = new ArrayList<>();
// Rust: Vec<Command>

// Java: Map<String, Integer> constToValue = new HashMap<>();
// Rust: HashMap<String, u16>  // Use appropriate integer type
```

**Watch out for:**
- `List.subList()` → use slices `&commands[start..end]`
- `Collections.sort()` → use `vec.sort()`
- Nullable collections → use `Option<Vec<T>>` or empty vec

---

### 7. **Labels Management** (`Labels.java`)
The nested `GlobalLabel` and `Label` classes with mutable `address` fields.

**Refactor to:**
```rust
// Java has mutable label addresses that get updated
// Rust: make addresses immutable, rebuild if needed
#[derive(Debug, Clone)]
struct Label {
    name: String,
    address: u16,
    location: Location,
    used: bool,
}

struct LabelMap {
    global: HashMap<String, Label>,
    current: Option<String>, // Track current global label for local labels
}
```

## 🟢 **LOW PRIORITY - Cosmetic Issues**

### 8. **Getter Methods**
Java has `command.get(0)`, `command.get16bitValue()`, etc.

**Refactor to:**
```rust
// Rust: use tuple structs or direct field access
struct Command {
    data: Vec<u8>,
    // ...
}

// Instead of:
command.get(0)  // Java

// Use:
command.data[0]  // Rust
// or create helper methods
impl Command {
    fn get(&self, index: usize) -> u8 { self.data[index] }
    fn get_u16(&self) -> u16 { ((self.data[0] as u16) << 8) | self.data[1] as u16 }
}
```

---

### 9. **String Handling**
Java uses `String`, `StringBuilder`, `text.toLowerCase(Locale.ROOT)`.

**Rust equivalents:**
```rust
// Java: StringBuilder buffer = new StringBuilder();
// Rust: String::new() or format!()

// Java: text.toLowerCase(Locale.ROOT)
// Rust: text.to_lowercase() or text.to_ascii_lowercase()
```

---

### 10. **File I/O**
Java uses `Path`, `Files.newBufferedReader()`, `IOException`.

**Rust:**
```rust
use std::fs::File;
use std::io::{BufReader, Read};
use std::path::Path;

// Java: Files.newBufferedReader(file)
// Rust:
let file = File::open(path)?;
let reader = BufReader::new(file);
```

## 💡 **Rust-Specific Patterns to Adopt**

```rust
// 1. Use enums for command types
#[derive(Debug, Clone, PartialEq)]
enum CommandType {
    Label,
    Org,
    Content,
    Align,
    LazyContent,
    AutoJump,
}

// 2. Use Option for nullable fields
struct Command {
    data: Option<Vec<u8>>,
    size: usize,
    text: String,
    location: Location,
}

// 3. Use Result for fallible operations
fn parse_file(path: &Path) -> Result<Vec<Command>, AssembleError> { ... }

// 4. Use iterators instead of for-loops with mutation
let resolved: Vec<_> = commands
    .into_iter()
    .filter_map(|c| resolve(c, &labels).ok())
    .collect();
```
